# IROBLEND

**Let's いろ BLEND!**

好きな色を2〜5色えらび、各色のスポイトを1〜5本分に変えながら混ぜられる、無料の色混ぜWebアプリです。PC、スマートフォン、タブレットの画面幅に合わせてレイアウトが変わります。

## 使い方

1. 色のグループを開き、色を2〜5色えらびます。選んだ色は白いキャンバスへ飛んで付着します。
2. 各色の空のスポイト5本から量を選びます。選んだ本数まで色が入り、最初はすべて3本分です。
3. 「まぜる！」を押します。混色アニメーションの後に色と近い色名が表示されます。
4. 混色後も色やスポイトの本数を変え、「もういちど まぜる！」で結果を比較できます。
5. 気に入った結果は「この色を保存する」で保存できます。「すべて消す」で選択だけを初期化し、保存した配合は後から呼び出せます。

保存した色はブラウザーの `localStorage` に残ります。ブラウザーのデータ削除や端末変更に備え、JSONの「書き出す」「読み込む」も用意しています。クラウド同期はありません。
旧モデルで保存した配合も読み込めます。表示する結果色と色名は現在の仮想絵の具セットで再計算されるため、以前保存した時の色とは異なる場合があります。

「スポイト1本分」は色を混ぜる**相対量**です。実際のスポイト1本の容量を表すものではありません。

## 開発

Node.js 24 と npm を使用します。

```sh
npm ci
npm run dev
```

検証と静的ビルド:

```sh
npm test
npm run build
```

`dist/` を静的サイトとして配信できます。ビルド後のアセット参照は相対パスなので、ルート配下とサブパス配下のどちらでも使えます。ログイン、バックエンド、Cookie、分析SDK、外部API通信はありません。

## 混色の考え方

54色それぞれに、表示用sRGB・色名・仮想顔料モデルを持たせています。顔料は表示用sRGBだけから推定せず、380〜750nm（10nm間隔、38点）の吸収K・散乱Sを独立に定義した基本顔料と、その明示的な配合から作ります。基本顔料の係数は手設計で、実測値ではありません。

混色は二定数Kubelka–Munk法の不透明・十分厚い層の近似です。スポイトの本数から濃度 `c_i = amount_i / total` を求め、`K_mix = Σ c_i K_i`、`S_mix = Σ c_i S_i` を別々に計算します。`q = K_mix / S_mix` から `R = 1 / (1 + q + sqrt(q² + 2q))` で反射率へ戻します。白は高散乱、黒は強吸収・低散乱です。比率3:1は3:1のまま混色へ渡ります。

子ども向けの予測しやすさを優先し、分光計算の後で単色の見本とのずれを補正します。複数の有彩色を混ぜる場合は、全色共通の赤・黄・青ベースの色相環から混色方向を決めます。赤＋青は紫、赤＋黄はオレンジ、黄＋青は緑へ向かい、赤・黄・青をさらに混ぜると茶色系へ収束します。白・黒は色相環に加えず、K/Sの散乱・吸収で明度を動かします。特定の2色だけを例外処理する方式でも、単純なRGB平均でもありません。

[Spectral.js 3.0.0](https://github.com/rvanwijnen/spectral.js)は反射率からOKLabへの変換と色見本の解析に使用します。色名は最終的な表示色とのOKLab距離で最も近いものを選び、「○○に近い色」と表示します。

実物の絵の具との完全一致は保証しません。顔料、紙、厚さ、乾燥、照明、画面によって見える色が変わります。この説明はアプリ内の「このアプリの色について」からも確認できます。

## キャンバスと混色アニメーション

選色時はCanvas 2Dで白い枠なしキャンバスへ色玉が飛び、連続したランダム座標に不規則な飛沫を残します。5色ができるだけ離れるよう近すぎる候補だけ再抽選し、飛沫が重なる部分だけ同じ混色モデルで混ぜて描きます。狭い画面では色を選ぶドロワーを閉じ、着弾が見えるようにします。

混色時はCanvas 2Dで840msの粒子流入・加速する軌跡・中央の衝突・短いマーブル状態・完成色への収束を描きます。最大115粒、DPR上限2で、WebGLや描画用ライブラリは不要です。再生終了・アンマウント時にはフレーム予約とリサイズ監視を解除します。`prefers-reduced-motion`では着弾動作を省き、混色も130msの色の切替に簡略化します。

## 白の量の調査と回帰テスト

旧処理のstate→選択色→混色関数に量の欠落、同一weight化、古いstate参照はありませんでした。ただし、sRGBから推定したK/Sを直接平均し、散乱Sを全色同一とするため、白の強い散乱を表現できませんでした。旧処理のレッド3＋ブルー3＋ホワイト1は `#625459`、白5は `#726469`（OKLab Lは約0.462→0.519）で、完全同色は再現せず、暗い灰色寄りの弱い変化を確認しました。

スポイトの本数だけを変えたときは前回の完成色をキャンバスに残し、「前にまぜた色」と明記します。「もういちど まぜる！」で新しい量の結果に切り替わります。色の追加・削除では選択色のキャンバスに戻ります。UI回帰テストでは白を1→5本分に変更しても前回色を維持し、混色完了時に最新の計算色が再描画されることを確認します。ドメインテストは指定の7性質をOKLabの色差・色相・明度で検証し、量の比率のスケール不変性、全54色の組合せ、独立した散乱の寄与、不正な分光データも確認します。

現在のモデルは白を増やすと3色以上でも明度が上がり、黒を増やすと下がります。基本顔料の曲線は手設計の近似であり、実測スペクトルへの校正は行っていません。

## 直感的な混色の検証と限界

全54色の単色見本との一致、赤＋青／赤＋黄／黄＋青、白・黒の量の差、代表的な3〜5色の配合をOKLabの色相・彩度・明度でテストします。多色では補色が打ち消し合い、茶色や灰色に近づく場合もあります。さらに無作為な3〜5色の配合で、スポイトを1本分変えたときに色が突然大きく飛ばないことを検証します。

このモデルは「色遊びで予想しやすい」仮想絵の具であり、特定メーカーの実物の絵の具への一致を目標にしていません。子どもによる色名の受け取り方や、54色のすべての多色組み合わせを実測で評価したものでもありません。
