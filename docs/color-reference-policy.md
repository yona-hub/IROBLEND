# 色名・見本・仮想顔料の参照基準

確認日: 2026-10-01

## 採用する基準

色名のHEXは、すべての用途で共通する普遍的な規格ではありません。IROBLENDでは次の優先順位を製品内の基準にします。

1. [洋色大辞典](https://www.colordic.org/y)に英名が完全一致する項目がある場合は、そのsRGB HEXを採用する。
2. 未掲載の場合に限り、[W3C CSS Color 4の色名](https://www.w3.org/TR/css-color-4/#named-colors)を使用する。大小文字・英名の空白を正規化し、別の名称を推測で同一視しない。
3. どちらにもない説明的な名前はIROBLEND独自の見本とし、`reference.kind: authored`と明記する。

共通レジストリは`src/data/namedColors.ts`。125項目の内訳は洋色大辞典78、CSS17、独自30です。選択色54色、カテゴリ見本、混色結果名の辞書、顔料の表示校正はこのレジストリを使います。独自項目を外部辞典の定義値として扱いません。95項目に外部参照があり、旧データから94項目のHEXが変更されました。

出典の名称が日常語の明暗関係と一致するとは限りません。例えばCSSのDark Grayは`#A9A9A9`で、洋色大辞典のGray `#7D7D7D`より明るい値です。CSSから採用した名前を「同系色より必ず暗い／明るい」という相対的な説明へ置き換えません。

### 名称の整理と保存互換性

| 保存用IDまたは旧名 | 採用する名前 | 理由 |
| --- | --- | --- |
| `milk-white` | ミルキーホワイト / Milky White | 辞典の掲載名を明示する |
| `charcoal` | チャコールグレー / Charcoal Gray | 辞典の掲載名を明示する |
| `dark-slate` | ダークスレートグレー / Dark Slate Gray | CSSの厳密名に合わせる |
| Umber / アンバー | ローアンバー / Raw Umber | Amberと異なる色を区別する |
| Amber / アンバーイエロー | アンバー / Amber | 洋色大辞典の名称・見本へ統一する |
| Cocoa、Sand、Wine | Cocoa Brown、Sand Beige、Wine Red | 対応する参照名を明示する |

選択色のID、スポイト量、保存形式は維持します。保存配合は既存の読込処理で現行モデルから再計算されるため、表示色・結果名は更新されます。

## グラファイトの原因と修正

参照は[グラファイト `#594E52`](https://www.colordic.org/colorsample/4280)。参照ページでは暗い赤紫系と説明されています。「茶色そのもの」を目標にはしていません。

旧見本`#4F545B`は青寄りでした。旧顔料も黒と白だけの配合で、表示補正と結果辞書がその独自見本を使っていたため、テストが通っても外部参照との色相差を検出できませんでした。

新見本は`#594E52`。黒白に赤・ローズ系の基本顔料を含め、補正前の色も`#584E52`へ近づけました。参照との補正前OKLab距離は約0.01750から0.001212へ低下し、補正後の表示は参照HEXと一致します。

## 顔料の点検とモデルの限界

380〜750nmの吸収K・散乱Sを持つ8つの基本顔料は変更していません。54色の配合は、非負・正規化した重みをオフラインで探索し、参照色とのOKLab距離を減らしました。元配合との比較で参照から遠くなる候補はありません。白・黒の基本顔料は保持しています。RGBからスペクトルを生成したものでも、実際の顔料を実測したものでもありません。

顔料の出典識別子は`authored-virtual-pigment-v3`です。見本校正はIDから共通レジストリを取得するため、呼出元が異なるHEXを渡せません。基本顔料の係数は手設計です。補正前の残差が大きい色もあり、黒は約0.242、プラムは約0.087、カーマインは約0.078です。有限のK/Sでは完全な黒`#000000`に届かず、鮮やかな色も8基本顔料の範囲に制約されます。補正前の物理的再現性と補正後の見本一致を区別します。

白黒グループにある微妙な色味も表示校正へ含めます。ただし共有RYB色相環ではこれらを有彩色として数えません。弱い色味が青・赤などと同じ票を持ち、混色方向を大きく動かすことを防ぐためです。

## 結果名の選び方

最終的に表示するsRGBをOKLabへ変換し、共通辞書の見本との距離で近い名前を選びます。独自のWarm Gray・Brown Gray・Greigeは黄み方向、Cool Grayは青み方向の候補に限定しました。OKLabのb成分に±0.003の中立域を設け、無彩色が明度差だけで黄み・青みグレーと呼ばれることを防ぎます。

これはこれらの説明的なグレー名の誤選択を防ぐ制約です。赤紫も含む色全般の普遍的な暖色・寒色判定ではありません。結果の名前は引き続き「○○に近い色」という目安です。

## 独立確認と検証結果

別エージェントが、取得した洋色大辞典285項目の名前・URL・HEX、共通125項目の優先順位と一意性、54顔料の候補配合とK/Sからの計算を独立に確認しました。参照照合の不一致は0件、候補の距離再計算との差は最大約0.000000126です。実装後も共通125項目と54配合を承認済み候補へ独立比較し、不一致0件を確認しました。保存IDの維持とグレー候補の制約も確認済みです。

自動検証は、外部取得スナップショットによる参照照合、グラファイトの色味、グレー候補の中立域、全色の白黒明度方向、全ペアの量増加方向、RYB混色、3〜5色の連続性、保存復元、飛沫の交差色、画面操作を含みます。

- 57テスト合格、本番ビルド成功。
- 全1,431通りの2色混色で無効な表示色は0件。
- 入力順序の変更、比率を保った量の倍率変更による表示差は0。
- 全54色の補正後の見本との差は0。

距離は0〜1スケールのOKLabユークリッド距離です。CIEDE2000の値ではありません。実物の絵の具の再現性やブラウザ・実機での見た目を実測した結果でもありません。

`npm run audit:colors`で`reports/color-consistency-audit.json`を再生成できます。参照・全配合・補正前後の色と距離・白黒の量変更・全ペアの結果を記録しています。参照先を更新するときは取得スナップショットも更新し、別名対応・配合・名前候補・関連テストを再確認してください。
